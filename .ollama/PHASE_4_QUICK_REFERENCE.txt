THE 3 CORE RULES (MEMORIZE THESE)
================================================================================

Rule 1: Only 1 Tier 4+ Model at a Time
  → OLLAMA_NUM_PARALLEL=1 enforces this
  → Never load 2 large models in parallel
  → Use serialization queue for workflows

Rule 2: Check Resources Before Tier 4+
  → Tier 4: Need 20GB free RAM, 4GB free VRAM
  → Tier 5: Need 25GB free RAM, 5GB free VRAM
  → Reject if insufficient resources

Rule 3: Unload Tier 5 Immediately After Use
  → Never keep 70B+ models resident
  → Set keep_alive=0 for cleanup
  → System stable ONLY with Tier 5 unloaded

Tier 1 (Embeddings):        nomic-embed-text, mxbai-embed-large
  → No load limit, use for semantic search anytime

Tier 2 (Small ≤8.5B):       qwen3:8b, phi4-14b:validator, gemma3:latest

  → ESCALATION ARBITRATION ONLY

  → Requires: 25GB free RAM check before load
  → CRITICAL: Unload immediately after use

NEVER DO THIS
================================================================================

✗ Load 2 Tier 4 models at the same time
  → Will violate OLLAMA_NUM_PARALLEL=1 constraint

✗ Keep Tier 5 model resident
  → Will consume 50GB+ RAM continuously

✗ Load model without checking free RAM/VRAM
  → Will cause OOM error or swap thrashing

✗ Invoke Tier 5 without user approval
  → Escalation level L5 = STOP & ASK

✗ Ignore timeout alerts
  → Will leave system in hung state


RESOURCE REQUIREMENTS
================================================================================

Tier 2 Load:     Min 8GB free RAM    Min 2GB free VRAM    Timeout 120s
Tier 3 Load:     Min 16GB free RAM   Min 3GB free VRAM    Timeout 180s
Tier 4 Load:     Min 20GB free RAM   Min 4GB free VRAM    Timeout 300s
Tier 5 Load:     Min 25GB free RAM   Min 5GB free VRAM    Timeout 600s


TIMEOUT RECOVERY
================================================================================

Tier 2 Timeout (120s):
  → Automatic recovery (no action needed)

Tier 3 Timeout (180s):
  → Manual: ollama rm <model_name>
  → Restart task or select lighter model

Tier 4 Timeout (300s):
  → Critical: Kill & restart Ollama
  → taskkill /IM ollama.exe /F
  → Wait 30s, restart Ollama

Tier 5 Timeout (600s):
  → System may be severely hung
  → Restart system recommended


COMMON WORKFLOWS
================================================================================

L0 Task (Quick):
  Load Tier 2 → Use → Unload automatically

L1-L2 Task (Medium):
  Load Tier 3 → Use → Unload
  Then: Load Tier 4 → Use → Unload

L3-L4 Conflict Resolution:
  Load Tier 4 Model A → Complete
  Load Tier 4 Model B → Review
  If disagree: Escalate to Tier 5 (needs approval)

L5 Escalation (Rare):
  STOP & ASK USER
  If approved:
    Prepare system (25GB+ free)
    Load Tier 5 → Use → UNLOAD IMMEDIATELY
    Consider restart


SERIALIZATION PATTERN
================================================================================

When Tier 4 model is requested and another model is running:

1. Check: curl http://localhost:11434/api/ps
   → If empty: Load model now
   → If busy: Continue to step 2

2. Wait for current model to finish
   → Up to timeout limit (180-300s)

3. Unload current model:
   curl -d '{"model":"<name>","keep_alive":"0"}' \
     http://localhost:11434/api/generate

4. Load new Tier 4 model
   → Should succeed (assuming resources available)

TROUBLESHOOTING
================================================================================

"Model load rejected - insufficient resources"
  → Free up RAM by closing apps or restarting
  → Or use lighter model (Tier 3 instead of Tier 4)

"Model timed out after 300s"
  → Inference likely hung
  → Restart Ollama service
  → Check Ollama logs for errors

"Out of memory error"
  → System ran out of RAM
  → Unload current model: curl http://localhost:11434/api/ps
  → Close other applications
  → Restart if necessary

"Tier 5 model keeps running"
  → Force unload: curl -d '{"model":"<name>","keep_alive":"0"}' ...
  → If still stuck, restart Ollama
  → Consider system restart


MONITORING
================================================================================

Monitor these during Tier 4/5 loads:
  1. GPU VRAM: nvidia-smi (should stay under 10GB)
  2. System RAM: Task Manager (should stay under 60GB used)
  3. Model status: curl http://localhost:11434/api/ps
  4. Inference time: Check response times (seconds per token)

Alert thresholds:
  ⚠️ VRAM > 8GB: GPU approaching limits, may use swap
  ⚠️ RAM > 55GB: System approaching limits
  ⚠️ Inference stuck 5+ min: Likely hung, consider kill
